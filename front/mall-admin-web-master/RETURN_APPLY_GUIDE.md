# 管理端用户退货申请处理指南

## 系统架构

本系统实现了完整的用户退货（退货申请）流程处理，分为**前端用户侧** 和 **后端管理侧** 两部分。

---

## 核心接口说明

### 1. **GET /returnApply/{id}** — 获取退货申请详情
- **用途**：浏览用户的退货原因、订单信息、凭证图片等完整信息
- **返回字段**：
  - `id`: 服务单号
  - `orderId`: 订单ID  
  - `orderSn`: 订单编号
  - `reason`: 用户提交的退货原因
  - `description`: 问题详细描述
  - `proofPics`: 凭证图片（逗号分隔）
  - `productRealPrice`: 商品实价
  - `productCount`: 商品数量
  - `status`: 当前状态（0=待处理, 1=退货中, 2=已完成, 3=已拒绝）
  - `memberUsername`: 用户账号
  - `returnName`: 退货联系人
  - `returnPhone`: 退货联系电话

### 2. **POST /returnApply/update/status/{id}** — 更新退货申请状态
- **用途**：管理员对用户退货申请进行处理决策
- **请求体**：
  ```json
  {
    "status": 1 或 3,  // 1=同意 3=拒绝
    "returnAmount": 100.00,  // 确认退款金额（同意时必填）
    "companyAddressId": 1,   // 收货点ID（同意时必填）
    "handleNote": "备注信息"  // 处理说明
  }
  ```

### 3. **GET /admin/returnApply/list** — 列表查询退货申请
- **用途**：管理员查看所有用户的退货申请列表
- **返回**：分页数据，包含 `records` 和 `total`

## 管理端处理流程

### 📋 三阶段流程

#### **阶段 1：待处理（Status = 0）**
管理员需要：
1. 点击"查看详情"按钮进入详情页
2. 查看用户提交的：
   - 退货原因
   - 问题描述
   - 凭证图片
3. 决策：**同意** 或 **拒绝**

**快速操作**：
- 在列表页直接点击"同意"或"拒绝"按钮（一键处理）
- 或进入详情页，选择确认退货或拒绝退货

#### **阶段 2：退货中（Status = 1）**
- 用户已收到同意消息，正在准备寄回商品
- 管理员等待用户寄出商品
- 收到用户寄回的商品后，管理员点击"确认收货"

#### **阶段 3：已完成（Status = 2）**
- 管理员已确认收货
- 记录收货人员、时间、备注等信息
- 流程结束，用户可获得退款

#### **已拒绝（Status = 3）**
- 管理员拒绝了用户的退货申请
- 用户无法继续处理该申请

## 前端用户侧流程

### 📱 用户退货流程

1. **用户在"我的订单"页面**
   - 对未发货的订单点击"退货"按钮
   - 弹出退货申请表单

2. **退货原因选择**
   - 显示商家提供的预设原因列表（来自 `/user/returnApply/list`）
   - 支持选择"其他（请填写）"并自定义原因

3. **提交退货申请**
   - 调用 `POST /user/returnApply/create`
   - 提交 `{ orderId, reason }`

4. **查看退货记录**
   - 用户可在"我的退货"页面查看所有退货申请及状态
   - 对接 `/user/returnApply/listAll` 接口

5. **订单列表状态标记**
   - 若订单存在"退货中"状态的申请，订单操作列显示"退货中"标签

## 快速开始

### 管理员操作流程

#### 方式 1：快速处理（推荐）
```
1. 进入 "订单 > 退货申请处理" 菜单
2. 查看待处理列表
3. 对每条申请：
   - 点击"查看详情"了解完整信息
   - 或直接点击"同意"/"拒绝"快速处理
```

#### 方式 2：详细处理
```
1. 进入 "订单 > 退货申请处理" 菜单
2. 点击"查看详情"按钮进入详情页
3. 详细查看：
   - 退货商品信息
   - 用户提交的原因和描述
   - 凭证图片
   - 选择收货点和退款金额
4. 点击"确认退货"或"拒绝退货"
5. 用户寄回商品后，点击"确认收货"完成流程
```

## 后端状态说明

| 状态值 | 状态名 | 含义 | 管理员操作 |
|-------|-------|------|----------|
| 0 | 待处理 | 用户已提交申请，等待管理员处理 | 同意 / 拒绝 |
| 1 | 退货中 | 管理员已同意，用户准备寄回商品 | 确认收货 |
| 2 | 已完成 | 管理员已收到商品，流程完成 | 仅查看 |
| 3 | 已拒绝 | 管理员拒绝了用户的退货申请 | 仅查看 |

## 常见问题

### Q1：如何快速处理大量待处理申请？
**A**：使用列表页的快速操作按钮（同意/拒绝），直接在列表视图处理，无需逐个进入详情页。

### Q2：确认退货后，用户需要做什么？
**A**：用户会收到同意消息和收货地址，按收货点邮寄商品，管理员收到后点击"确认收货"完成流程。

### Q3：能否修改已处理的申请？
**A**：当前系统中，状态为 1、2、3 时的申请为已处理状态，表单输入被禁用，无法直接修改。如需更正，建议联系系统管理员。

### Q4：拒绝退货后用户会看到什么？
**A**：用户的"我的退货"页面会显示该申请状态为"已拒绝"，用户可在该页面查看拒绝原因。

## 维护建议
